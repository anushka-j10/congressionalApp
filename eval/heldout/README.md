# Held-out test protocol — do not inspect during development

The student supplies ten synthetic notices and expected-field files here. No test
samples have been generated by Codex. The template describes the format, not a
real test case; exclude it from the final manifest.

Do not open, OCR, debug, tune, or run these samples during Parts A–C or the fix loop.
After the chosen fixes (maximum three rounds), freeze the code with `eval-freeze`.
Only then run the held-out evaluator once. A run-start ledger must be created
before reading any sample, so a crash or provider failure cannot silently turn into
a second test attempt. Report missing/unavailable results as they are. Do not change
code or re-run held-out after seeing its outcomes.

Provide manifest.json with {"synthetic":true,"samples":["case_01.json", ...]}.
Use paths relative to this folder and invented people, addresses and identifiers.
Keep the expected-fields JSON inaccessible to the model; it is for scoring only.
